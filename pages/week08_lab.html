Before You Start

This lab sets up the GitHub workflow you will use for every remaining assignment. Plan on about an hour. The first push is the slow part, and after this lab each submission takes a couple of minutes. Read Setting up Git and GitHub in the lecture first. It explains why each setup step exists.

The big picture

You make an empty repo on github.com, clone it to your laptop, add files, commit them (a snapshot saved on your laptop), and push them (send the snapshots to GitHub). Then you submit the repo's URL to Canvas. Your instructor grades what is on github.com, not what is on your laptop.

What you need

  • A laptop with Git installed. You check this in Exercise 1.
  • Your USF email, for the GitHub account.
  • Your Module 7 functions.py. If you can't find it, download it from your Module 7 submission in Canvas.
  • VS Code, which you installed during Pre-Course Setup.

Where to type the commands

Open VS Code, then choose View → Terminal. The terminal opens at the bottom of the window. Every command in this lab goes there. Mac users can use the Terminal app instead. Windows users can use PowerShell or Git Bash. All the commands in this lab work in any of them.

How to read the command boxes

  • Type one line at a time, and press Enter after each one.
  • Lines that start with # are notes for you. Do not type them. The same goes for anything after a # at the end of a line.
  • Replace the placeholders. YOURUSERNAME, Your Name, and you@usf.edu stand for your own information. Leave the quotation marks in place.
  • Lost? Run git status. It changes nothing. It tells you which folder you are in, what has changed, and whether GitHub is behind your laptop.

Exercises

EXERCISE 1
BASIC
Create the account
If you do not have one, create a github.com account using your USF email. Set a professional username — this will appear on your portfolio. Enable two-factor authentication while you are there.

VERIFICATION

# You should be able to log in at github.com and see your profile page

CHECK THAT GIT IS INSTALLED

git --version     # you should see something like: git version 2.45.1

ONE-TIME SETUP: TELL GIT WHO YOU ARE

# Run once per computer. Use the email on your GitHub account.
# Without this, your first commit stops with "Author identity unknown".
git config --global user.name "Your Name"
git config --global user.email "you@usf.edu"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"

git config --global --list     # confirm all four are set
Hint: "git: command not found" or "'git' is not recognized"

Git is not installed yet, or your terminal opened before you installed it.

  • Mac: run xcode-select --install, click Install in the window that appears, and wait for it to finish.
  • Windows: download Git for Windows from git-scm.com/downloads and keep every default option in the installer.

Then quit and reopen VS Code, or your terminal app, and run git --version again. A terminal that was already open will not find the new install.

Hint: I already have a personal GitHub account

Keep it. You don't need a second account. Add your USF email under GitHub → Settings → Emails. Make sure the user.email you give Git is one of the emails listed there, so your commits show up under your name.

Hint: setting up two-factor authentication

Use an authenticator app on your phone, such as Google Authenticator, Microsoft Authenticator, or Duo Mobile, to scan the QR code GitHub shows you. Download or screenshot the recovery codes when GitHub offers them. If you lose your phone, those codes are the only way back into your account.

Hint: what do the last two config lines do?

init.defaultBranch main makes Git name the first branch main, which matches GitHub. core.editor "code --wait" makes Git open VS Code when it needs you to type a message, instead of an editor you can't exit. The lecture explains both.

Mac users: the editor setting needs the code command. Test it by typing code --version. If you see "command not found," open VS Code, press Cmd+Shift+P, type shell command, and choose Install 'code' command in PATH. Windows installs this command automatically. If you ever end up in the other editor anyway, the Troubleshooting table below shows how to get out.

EXERCISE 2
BASIC
New repo
On github.com, click New repository. Name it ism2411. Make it Public. Add a README. Clone it to your local machine.

ALREADY HAVE AN ism2411 FOLDER?

# In Module 2 you made a folder named ism2411. Git will not clone into a
# folder that already has files in it. You would see:
#   fatal: destination path 'ism2411' already exists and is not an empty directory.
#
# Rename the old folder first. Nothing is deleted. Your earlier work is
# still inside ism2411-old. Run this from the folder that contains it
# (usually your home folder):
mv ism2411 ism2411-old

COMMANDS

# Go to your home folder first, so the repo lands somewhere easy to find
cd ~

# Clone the repo to your local machine
git clone https://github.com/YOURUSERNAME/ism2411.git

# Navigate into it
cd ism2411

# Verify Git is tracking it
git status       # should say: On branch main ... nothing to commit, working tree clean

# Open the repo in VS Code (or use File → Open Folder and pick ism2411)
code .
Hint: which boxes do I check on the New repository page?
  • Repository name: ism2411, all lowercase.
  • Public. Your instructor can't grade a private repo.
  • Add a README file: check it. This gives the repo its first commit, so you can clone it.
  • Add .gitignore: leave it at None. You write your own in Exercise 3.
  • License: leave it at None.
Hint: where do I get the URL for git clone?

On your repo's page on github.com, click the green Code button, make sure the HTTPS tab is selected, and click the copy icon. The URL ends in .git. Paste it after git clone.

Hint: don't clone inside another repo

Run git clone from your home folder (cd ~), not from inside ism2411-old or any other project folder. If you're not sure where you are, pwd prints the folder your terminal is in. Every command in Exercises 3 through 6 must be run from inside the new ism2411 folder.

EXERCISE 3
BASIC
Add a .gitignore
Create a .gitignore file in your repo root. Add common Python and OS exclusions, then commit and push it before adding any other files.

STARTER .gitignore CONTENT

# Python
__pycache__/
*.pyc
*.pyo
.env
*.egg-info/

# OS
.DS_Store
Thumbs.db

# Editors
.vscode/
.idea/

COMMIT COMMANDS

git add .gitignore
git commit -m "add .gitignore for Python and OS files"
git push

FIRST PUSH: SIGNING IN

Your first git push asks you to prove who you are. If a browser window opens, sign in to GitHub and approve. If the terminal asks for a username and password, type your GitHub username and paste a personal access token as the password. GitHub stopped accepting account passwords for Git in 2021.
  1. Go to github.com → Settings → Developer settings → Personal access tokens → Tokens (classic).
  2. Click Generate new token (classic). Give it a name (for example, “ISM2411 laptop”) and check the repo scope.
  3. Click Generate token and copy it right away. It is shown only once.
  4. Paste it when Git asks for your password. Nothing appears on screen while you paste. That is normal.
Hint: how do I create a file that starts with a dot?

Use VS Code, not Finder or Notepad. In the Explorer panel on the left, hover over the ISM2411 heading, click the New File icon, and type .gitignore exactly: a dot first, then no extension. Paste in the starter content and save with Cmd+S or Ctrl+S.

  • The file must sit at the top level of ism2411/, next to README.md, not inside a subfolder.
  • Notepad on Windows secretly saves it as .gitignore.txt, and then Git ignores it. Run ls -a (or ls -Force in PowerShell) to see the real name.
  • Mac Finder hides files that start with a dot. The file is there. Press Cmd+Shift+. in Finder to show hidden files.
Hint: git status shows nothing after I made the file

The file probably isn't saved yet. In VS Code, an unsaved file has a white dot on its tab instead of an ×. Save it, then run git status again. You should see .gitignore listed under "Untracked files".

Hint: setting the token's expiration date

GitHub sets new tokens to expire in 30 days. That date falls before the end of the semester. When a token expires, git push fails with "Authentication failed". To avoid that, open the Expiration menu and choose Custom, then pick a date after finals week. Keep the token somewhere private, such as a password manager. Never paste it into a file in your repo.

Hint: how do I paste into the terminal?

In VS Code's terminal, press Cmd+V on a Mac or Ctrl+V on Windows. In Git Bash, right-click and choose Paste, or press Shift+Insert. Paste once and press Enter. Nothing appears on screen while you paste, so don't paste a second time.

EXERCISE 4
INTERMEDIATE
Add Module 7 work
Copy your functions.py from Module 7 into a new folder ism2411/week07/. Stage, commit, and push it with a descriptive message.

COMMANDS

# From inside ism2411/:
mkdir week07

# Replace the path with wherever your Module 7 file is. If you renamed
# your old folder in Exercise 2, look inside it:  ls ../ism2411-old
cp /path/to/your/functions.py week07/

git status            # confirm Git sees the new file
git add week07/
git commit -m "add module 7 functions: calculate_tax, apply_discount, final_price"
git push

VERIFICATION

# Visit https://github.com/YOURUSERNAME/ism2411
# You should see the week07/ folder and your commit message
Hint: I don't know the path to my functions.py

Type cp (with a space after it), then drag functions.py from Finder or File Explorer into the terminal window. The terminal fills in the full path for you. Then type a space and week07/, and press Enter.

You can also skip the terminal for this step. Drag the file into the week07 folder in VS Code's Explorer panel, then continue with git status.

Hint: I can't find my Module 7 file at all

Open Canvas, go to your Module 7 lab submission, and download the functions.py you uploaded. Move it into ism2411/week07/. Make sure the file is named exactly functions.py, not functions (1).py or functions.py.txt.

Hint: git status doesn't show week07/

Git ignores empty folders. If the copy did not work, week07/ is empty and Git acts as if it isn't there. Run ls week07. If functions.py is not listed, repeat the copy step.

EXERCISE 5
INTERMEDIATE
Write a README
Open README.md. Add: a title (# ISM2411 — Python for Business), your name, semester, and a short description of the repo. Use markdown headings and bullet lists. Commit and push.

README TEMPLATE

# ISM2411 — Python for Business

**Name:** Your Name Here

**Semester:** Fall 2026

**Instructor:** [Course Instructor]

## About This Repo

This repository contains my weekly lab submissions for ISM2411.
Each folder corresponds to one module.

## Modules

- `week05/` — Conditionals: tiered discount calculator
- `week06/` — Loops: sales report with sum, average, max
- `week07/` — Functions: calculate_tax, apply_discount
- `week08/` — Git: first GitHub submission

## How to Run

Each script is standalone. Open a terminal and run:
```
python week07/functions.py
```

COMMIT COMMANDS

git add README.md
git commit -m "add README with module listing and run instructions"
git push
Hint: edit the README in VS Code, not on github.com

GitHub lets you edit files on the website. Don't do that in this lab. An edit on the website creates a commit that your laptop doesn't have, and your next git push is rejected. If that already happened, run git pull, then git push. The Troubleshooting table covers this.

Hint: what goes in the README?

Open README.md in VS Code. GitHub already put a single line in it. Select everything, delete it, and paste the template above. Then replace Your Name Here and [Course Instructor] with real names. Only list folders that actually exist in your repo. If you don't have week05/ or week06/ folders, delete those lines.

To see the formatted version while you type, press Cmd+Shift+V on a Mac or Ctrl+Shift+V on Windows. VS Code opens a preview.

EXERCISE 6
INTERMEDIATE
Three commits
Make at least 3 separate commits this module with descriptive messages. Each commit should be for a distinct, coherent change — not "update everything at once." Run git log --oneline to verify all three appear. Confirm each shows up on github.com.

EXPECTED git log OUTPUT (NEWEST FIRST)

f7c2b3e add README with module listing and run instructions
a3f1b2c add module 7 functions: calculate_tax, apply_discount, final_price
9d4e1a0 add .gitignore for Python and OS files
4b8d2c1 Initial commit
Your hashes will be different. The bottom line, Initial commit, is the one GitHub made when you checked Add a README. It does not count toward your three.
Hint: do I need to make new commits for this exercise?

Probably not. If you finished Exercises 3, 4, and 5, you already have three commits: .gitignore, week07/, and the README. This exercise checks that they are there and that each one has a clear message.

Hint: git log shows my commits, but github.com doesn't

You committed but didn't push. Run git status. If it says Your branch is ahead of 'origin/main' by 2 commits, run git push and refresh the page on github.com.

Hint: git log filled the screen and I can't type

Git is showing the log one page at a time. Press q to quit and return to the prompt.

Troubleshooting

Read the last line of an error first. It usually says what went wrong. Find it in the left column below.

You seeWhat it means and how to fix it
fatal: not a git repositoryYour terminal is not inside the ism2411 folder. Run cd ~/ism2411, then try again. pwd shows where you are.
Author identity unknownGit doesn't know your name and email yet. Run the two git config --global user... lines from Exercise 1, then commit again.
Support for password authentication was removedYou typed your GitHub password. Git needs a personal access token instead. Make one (Exercise 3), run git push again, and paste the token as the password.
Authentication failed or 403 or Permission deniedThe token was typed wrong, has expired, or is missing the repo scope. Or your computer saved the wrong login. Clear the saved login, then push again and paste a fresh token.
Mac: open Keychain Access, search github.com, and delete the entry.
Windows: open Credential Manager → Windows Credentials, and remove git:https://github.com.
! [rejected] main -> main (fetch first)GitHub has a commit your laptop doesn't have, usually from editing a file on the website. Run git pull, then git push. If VS Code opens with a merge message, save and close that tab.
nothing added to commit but untracked files presentYou skipped git add. Run git add with the file or folder name, then commit again.
nothing to commit, working tree cleanGit sees no changes. Either the change is already committed, or the file isn't saved. Save in VS Code and run git status.
fatal: destination path 'ism2411' already existsAn ism2411 folder is already there. Rename the old one with mv ism2411 ism2411-old (Exercise 2), then clone again.
The terminal fills with ~ lines and won't let you type normallyYou ran git commit without -m, and Git opened the Vim editor. Press Esc, type :q!, and press Enter to get out. Then commit again with -m "your message". To keep it from happening again, run the core.editor line from Exercise 1.
The terminal shows (END) or a : at the bottomGit is showing long output one page at a time. Press q to quit.
Still stuck?

Copy three things: the exact command you ran, the full error message, and the output of git status. Paste them as text, not a screenshot. Post them to the Canvas discussion board, or bring them to office hours. With those three things, most Git problems take two minutes to fix. Never share your personal access token, not even with your instructor.

What to Submit to Canvas

Canvas Deliverable

Submit to Canvas: your GitHub repository URL only (e.g., https://github.com/yourusername/ism2411). Do not upload any files directly to Canvas.

Your repo must show, visible on github.com:

  1. A .gitignore file, committed before any of your own files. (GitHub’s Initial commit with the README comes first. That is expected.)
  2. A week07/ folder containing your functions.py from Module 7.
  3. A README.md with a title, your name, semester, and a description of the repo, plus a ## Reflection section answering all three Self-Assessment questions.
  4. At least 3 separate commits with descriptive messages in the repo's commit history (visible via git log --oneline or the GitHub “commits” view).
Check before you submit

Your instructor sees exactly what a stranger sees. Check your repo the same way:

  • Open a private or incognito browser window and go to https://github.com/YOURUSERNAME/ism2411. If you get a 404 page, the repo is private or the URL is wrong. To make it public, go to Settings → General → Danger Zone → Change visibility.
  • The file list shows .gitignore, README.md, and week07/. Click week07/ to make sure functions.py is inside it.
  • The README shows at the bottom of the page with your name and a Reflection section.
  • Click the commit count (the clock icon above the file list). You should see at least three commits besides Initial commit.
  • Run git status on your laptop. It should say Your branch is up to date with 'origin/main'. If it says "ahead", run git push.
  • Copy the URL from your browser's address bar on the repo's main page, and paste it into Canvas. Don't use the link to a single file.
