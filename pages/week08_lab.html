Before You Start

This lab sets up the GitHub workflow you will use for every remaining assignment. Plan on about 45 minutes. Everything happens in your web browser on github.com. After this lab, each submission takes a couple of minutes. The lecture explains what Git and GitHub are for. It shows Git commands in a terminal, but the ideas are the same: a repo, commits, and commit messages.

The big picture

You make a repo (a project folder) on github.com and upload your files to it through the website. GitHub saves each upload or edit as a commit: a snapshot of the repo with a short message that says what changed. Then you submit the repo's URL to Canvas. Your instructor grades what is on github.com, not what is on your laptop.

What you need

  • A web browser: Chrome, Edge, Firefox, or Safari.
  • Your USF email, for the GitHub account.
  • Your Module 7 functions.py. If you can't find it, download it from your Module 7 submission in Canvas.

How to read the steps

  • Bold words are buttons and menus on github.com. Add file → Upload files means: click the Add file button, then choose Upload files from its menu.
  • Replace the placeholders. YOURUSERNAME and Your Name stand for your own information.
  • Write your own commit message every time. GitHub fills in a message for you, such as Add files via upload or Update README.md. Replace it with one that says what you changed. Your commit messages are part of the grade.

Create the account

Use an authenticator app on your phone, such as Google Authenticator, Microsoft Authenticator, or Duo Mobile, to scan the QR code GitHub shows you. Download or screenshot the recovery codes when GitHub offers them. If you lose your phone, those codes are the only way back into your account.

EXERCISE 2
BASIC
New repo
On github.com, make a new repository named ism2411. Make it Public and add a README.

STEPS

  1. Click the + at the top right of any GitHub page, then New repository.
  2. Name it ism2411, all lowercase.
  3. Choose Public.
  4. Turn on Add README. Leave .gitignore and License set to none.
  5. Click Create repository.

VERIFICATION

# Your repo page, https://github.com/YOURUSERNAME/ism2411,
# lists README.md and shows 1 Commit
Hint: why those settings?
  • Public: your instructor can't open a private repo, so it can't be graded.
  • Add README: GitHub makes the repo's first commit, called Initial commit, with a one-line README.md in it. You fill in the README in Exercise 5.
  • .gitignore: none. You write your own in Exercise 3.
Hint: I already made an ism2411 repo

Use it. Don't make a second one. If it is Private, make it Public: open the repo, then Settings → General, scroll down to Danger Zone, and click Change visibility.

Hint: what about the ism2411 folder on my laptop from Module 2?

Leave it where it is. Nothing on your laptop changes in this lab. You upload copies of your files, and the folders on your laptop stay as they are.

EXERCISE 3
BASIC
Add a .gitignore
Create a .gitignore file at the top of your repo with common Python and OS exclusions. Commit it before you add any other files.

STEPS

  1. On your repo page, click Add file → Create new file.
  2. In the name box at the top, type .gitignore exactly: a dot first, and no extension.
  3. Paste the starter content below into the big editing box.
  4. Click Commit changes... at the top right. In the box that opens, replace the message with add .gitignore for Python and OS files. Leave Commit directly to the main branch selected, and click Commit changes.

STARTER .gitignore CONTENT

# Python
__pycache__/
*.pyc
*.pyo
.env
*.egg-info/

# OS
.DS_Store
Thumbs.db

# Editors
.vscode/
.idea/
Hint: what is a .gitignore for?

It lists files that don't belong in a repo, such as the __pycache__ folders Python makes and the .DS_Store files Macs make. Git leaves those files out when you commit from a terminal. Every professional Python repo has one. When you upload through the website, you choose each file yourself, so upload only the files a lab asks for.

Hint: GitHub showed a "Choose .gitignore template" button

GitHub offers ready-made lists once you type the name. For this exercise, skip it and paste the starter content above. From Lab 11 on, you pick GitHub's Python template when you make each repo.

Hint: why make the file on the website instead of uploading it?

Files that start with a dot are awkward on a laptop. Mac Finder hides them, so you can't see the file to drag it. Windows Notepad quietly saves the file as .gitignore.txt. Making it on the website avoids both problems.

Hint: the file shows up inside a folder

You typed a / in the name box. A / there makes a folder. Open the file, click the pencil icon (Edit this file), and fix the name box so it says only .gitignore. Commit the change.

EXERCISE 4
INTERMEDIATE
Add Module 7 work
Upload your functions.py from Module 7 into a folder named week07/ in your repo, with a descriptive commit message.

STEPS

  1. On your laptop, make a folder named week07 (on your Desktop is fine) and put a copy of your functions.py in it. In Mac Finder, use File → New Folder. In Windows File Explorer, use New → Folder.
  2. On your repo page, click Add file → Upload files.
  3. Drag the whole week07 folder, not just the file, from Finder or File Explorer onto the upload area. GitHub keeps the folder, so the file lands at week07/functions.py.
  4. Under Commit changes at the bottom, replace Add files via upload with add module 7 functions: calculate_tax, apply_discount, final_price, and click Commit changes.

VERIFICATION

# Your repo page lists a week07 folder.
# Click it: functions.py is inside, next to your commit message.
Hint: functions.py landed at the top, not in week07/

You dragged the file instead of the folder, or you used choose your files, which picks files only. Move it: click functions.py, click the pencil icon (Edit this file), click at the start of the name box, and type week07/ in front of functions.py. The / turns week07 into a folder. Click Commit changes..., write move functions.py into week07/, and commit.

Hint: drag and drop doesn't work for me

Copy and paste the code instead. Click Add file → Create new file and type week07/functions.py in the name box. Open functions.py in VS Code, select all of it (Cmd+A or Ctrl+A), copy, and paste it into the big editing box on GitHub. Commit it with the message above.

Hint: I can't find my Module 7 file at all

Open Canvas, go to your Module 7 lab submission, and download the functions.py you uploaded. Make sure the file is named exactly functions.py, not functions (1).py or functions.py.txt.

EXERCISE 5
INTERMEDIATE
Write a README
Edit README.md on github.com. Add a title (# ISM2411 — Python for Business), your name, the semester, and a short description of the repo. Use markdown headings and bullet lists. Commit the change.

STEPS

  1. On your repo page, click README.md in the file list, then the pencil icon (Edit this file).
  2. Delete the one line GitHub put there and paste the template below. Replace Your Name Here and [Course Instructor] with real names.
  3. Click the Preview tab to see the formatted version. Click Edit to go back.
  4. Click Commit changes..., replace the message with add README with module listing and run instructions, and click Commit changes.

README TEMPLATE

# ISM2411 — Python for Business

**Name:** Your Name Here

**Semester:** Fall 2026

**Instructor:** [Course Instructor]

## About This Repo

This repository contains my weekly lab submissions for ISM2411.
Each folder corresponds to one module.

## Modules

- `week05/` — Conditionals: tiered discount calculator
- `week06/` — Loops: sales report with sum, average, max
- `week07/` — Functions: calculate_tax, apply_discount

## How to Run

Each script is standalone. Open a terminal and run:
```
python3 week07/functions.py
```
Hint: what goes in the README?

Only list folders that actually exist in your repo. If you don't have week05/ or week06/ folders, delete those lines. The README shows at the bottom of your repo page, so it is the first thing a visitor reads.

Hint: I lost my changes before committing

GitHub doesn't save an edit until you commit it. If you closed the tab or clicked away, open the file and paste the template again. Commit as soon as the README looks right in Preview. You can always edit it again later, and each edit is a new commit.

EXERCISE 6
INTERMEDIATE
Three commits
Make at least 3 separate commits this module with descriptive messages. Each commit should be for a distinct, coherent change — not "update everything at once." Open your repo's commit history to check that all three are there.

HOW TO SEE YOUR COMMITS

On your repo page, click the commit count (the clock icon with 4 Commits, at the right above the file list). GitHub lists your commits, newest first:
add README with module listing and run instructions
add module 7 functions: calculate_tax, apply_discount, final_price
add .gitignore for Python and OS files
Initial commit
Each row also shows your username, the date, and a short code such as a3f1b2c. That code is the commit's ID, and yours will be different. The bottom one, Initial commit, is the one GitHub made when you turned on Add README. It does not count toward your three.
Hint: do I need to make new commits for this exercise?

Probably not. If you finished Exercises 3, 4, and 5, you already have three commits: .gitignore, week07/, and the README. This exercise checks that they are there and that each one has a clear message.

Hint: my messages say "Add files via upload", "Create .gitignore", or "Update README.md"

Those are the messages GitHub fills in when you don't write your own. They still count as commits, but they tell a reader nothing. The website can't change an old message, so make your next commits descriptive. If fewer than three of your commits have clear messages, make another real change, such as adding a line to your README, and give it a clear message.

Optional: Use Git from the Terminal

This is the way the lecture and the walkthrough videos show. It gives you the same repo, files, and commits as the website. Skip this section if the website steps worked for you.

Show the terminal steps

Where to type: in VS Code, choose View → Terminal. Type one line at a time and press Enter. Don't type the lines that start with #.

1. Check Git and tell it who you are (once per computer):

git --version     # you should see something like: git version 2.45.1
git config --global user.name "Your Name"
git config --global user.email "you@usf.edu"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"

If you see git: command not found: on a Mac, run xcode-select --install. On Windows, install Git for Windows from git-scm.com/downloads with the default options. Then quit and reopen VS Code.

2. Make the repo on github.com (Exercise 2), then clone it from your home folder. If you already have an ism2411 folder from Module 2, rename it first with mv ism2411 ism2411-old, because Git won't clone into a folder that has files in it.

cd ~
git clone https://github.com/YOURUSERNAME/ism2411.git
cd ism2411
code .

To get the URL, click the green Code button on your repo page, choose HTTPS, and copy it.

3. Make, commit, and push each change. Make .gitignore in VS Code's Explorer with the New File icon, then:

git add .gitignore
git commit -m "add .gitignore for Python and OS files"
git push

mkdir week07
cp /path/to/your/functions.py week07/
git add week07/
git commit -m "add module 7 functions: calculate_tax, apply_discount, final_price"
git push

# After editing README.md in VS Code and saving it:
git add README.md
git commit -m "add README with module listing and run instructions"
git push

git log --oneline     # your commits, newest first (press q to quit)

Signing in on your first push: if a browser window opens, sign in and approve. If the terminal asks for a password, paste a personal access token, not your GitHub password. Make one at github.com → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic). Check the repo scope, set the expiration to a date after finals week, and copy the token right away. Nothing appears on screen while you paste it.

Mixing both ways: you can switch between the terminal and the website, but after any upload or edit on the website, run git pull before your next git push. Never share your personal access token, not even with your instructor.

What to Submit to Canvas

Canvas Deliverable

Submit to Canvas: your GitHub repository URL only (e.g., https://github.com/yourusername/ism2411). Do not upload any files directly to Canvas.

Your repo must show, visible on github.com:

  1. A .gitignore file, committed before any of your own files. (GitHub’s Initial commit with the README comes first. That is expected.)
  2. A week07/ folder containing your functions.py from Module 7.
  3. A README.md with a title, your name, semester, and a description of the repo, plus a ## Reflection section answering all three Self-Assessment questions.
  4. At least 3 separate commits with descriptive messages in the repo's commit history (click the commit count on your repo page to see them).
Check before you submit

Your instructor sees exactly what a stranger sees. Check your repo the same way:

  • Open a private or incognito browser window and go to https://github.com/YOURUSERNAME/ism2411. If you get a 404 page, the repo is private or the URL is wrong. To make it public, go to Settings → General → Danger Zone → Change visibility.
  • The file list shows .gitignore, README.md, and week07/. Click week07/ to make sure functions.py is inside it.
  • The README shows at the bottom of the page with your name and a Reflection section.
  • Click the commit count (the clock icon above the file list). You should see at least three commits besides Initial commit, each with a message that says what changed.
  • Copy the URL from your browser's address bar on the repo's main page, and paste it into Canvas. Don't use the link to a single file.
