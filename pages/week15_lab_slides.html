Teaching goal: .groupby().sum().reset_index() as a repeatable three-step recipe, and a first properly-labeled bar chart — the template every remaining chart in this lab (and the capstone) will follow. Say to the class (verbatim): "First business question: which region makes the most money? One aggregation, one bar chart, one sentence stating the answer as a number." Line-by-line: df.groupby("region")["revenue"].sum() — read as three steps left to right: group the DataFrame into buckets, one per distinct region; pull out just the "revenue" column from each bucket; sum it within each bucket — one total per region. .reset_index() — worth explaining, not boilerplate: a raw groupby(...).sum() uses the grouped column (region) as its index, not an ordinary column, which is awkward for charting and sorting; .reset_index() converts that index back into a normal column, giving a clean two-column DataFrame (region, revenue) — memorize "groupby, then reset_index" as a unit. .sort_values("revenue", ascending=False) — Module 13's sort applied to the aggregated result so both the printed table and the chart show regions highest-first. fig, ax = plt.subplots(figsize=(8, 5)) — new syntax: creates a figure (fig, the canvas) and an axes (ax, the plotting area) together; nearly everything forward is a method call on ax, and this is the standard professional pattern, not the plt.bar(...) shortcut. ax.bar(region_revenue["region"], region_revenue["revenue"], color="#4C72B0") — region values become x-axis categories, revenue values become bar heights. ax.set_title(...), ax.set_xlabel(...), ax.set_ylabel(...) — all three required explicitly; an unlabeled chart, even a correct one, does not meet the standard. plt.tight_layout() — adjusts spacing so labels/titles are not cut off; a cheap habit on every chart. Teaching goal: extract a month from a datetime column, aggregate by it, and confront a genuine, easy-to-miss gotcha: groupby only shows months that actually appear in the data — a month with zero orders simply vanishes from the result unless explicitly handled. Say to the class (verbatim): "Second question: how does revenue move across the year? The lab page requires all 12 months on the x-axis — and I want to show you why that requirement isn't automatic, because it genuinely trips people up." Line-by-line: pd.to_datetime(df['order_date']) — parses the date column to a real datetime type; echoing Module 14 Exercise 7's gotcha, if clean_sales.csv was saved and reloaded without parse_dates, order_date likely came back as object (text) — this line (re-)converts it. df['order_date'].dt.month — .dt is a specialized accessor available only on genuine datetime columns; .month extracts the month number (1–12) from each date — analogous to Module 13's .str accessor. df.groupby("month")["revenue"].sum() — Exercise 1's exact aggregation pattern, grouping by month instead of region. .reindex(range(1, 13), fill_value=0) — the exercise's real payoff line: forces the result to have exactly index values 1–12, inserting fill_value=0 for any missing from the grouped result; this is the general, reliable pattern for "make sure every expected category appears, even ones with zero activity." ax.plot(monthly.index, monthly.values, marker='o') — a line chart with a circular marker at each real data point. ax.set_xticks(range(1, 13)) — a second, chart-level safeguard forcing a tick for every month 1–12 regardless of the plotted data. Required one-sentence finding: "December was the peak month at $63,641.59 in revenue, about 94% above the monthly average — consistent with a genuine holiday-season sales pattern." Common mistakes: skipping .reindex() because "it happened to work anyway" on their specific dataset (every month having at least one order by chance) — a fragile script likely to break silently on the capstone's actual data or any future month with a genuine sales gap. Calling .dt.month on a column still object dtype (forgot pd.to_datetime()) — raises AttributeError: Can only use .dt accessor with datetimelike values. The idea — groupby shows only the months that appear; .reindex() forces all 12

A month with zero orders is absent, not zero

df.groupby("month")["revenue"].sum() produces one row per month that actually occurs in the data. If February had zero orders, February is not a 0 row — it is simply not there. The exercise requires all 12 months on the x-axis regardless.

monthly.reindex(range(1, 13), fill_value=0) forces the index to be exactly 1…12, inserting 0 for any missing month. This is the general pattern for "every expected category must appear, even ones with zero activity" — it works for regions, products, anything. ax.set_xticks(range(1, 13)) is a second, chart-level safeguard for the same requirement.
