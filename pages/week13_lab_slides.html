Learning objectives

By the end of this 75-minute session, students should be able to:

  • Load a CSV into a DataFrame with pd.read_csv() and inspect its shape, columns, and dtypes.
  • Explain what a boolean filter (df[df['region'] == 'South']) actually does — construct a column of True/False, then keep only the True rows.
  • Combine two conditions with &, and explain why both parentheses and & (not and) are required, not stylistic.
  • Create a new column from existing ones with a single vectorized assignment, with no loop.
  • Use .unique() and .value_counts() to understand what values live in a column and how often.
  • Save a DataFrame back to CSV with .to_csv().

Filter by Region

Teaching goal: the single most important mental model in this entire lab — df[df['region'] == 'South'] is not a "search"; it is built from a column of True/False values, and the outer brackets keep only the True rows. Get this right and every remaining filtering exercise this semester makes sense; get it wrong and pandas filtering stays permanently mysterious. Say to the class (verbatim): "This next line looks like magic the first time you see it, so we're going to take it apart in two separate steps before running it as one line. This is the single most important idea in today's whole lab."

The idea — a filter is a column of True/False

Slow down — this is the whole lab

df['region'] == 'South' produces a brand-new column — not a filtered table, not a search result — a column of True/False, one value per row, the same length as the whole DataFrame, saying whether that specific row matches.

df[ ... ] around that column reads as "keep only the rows where this is True." Build a True/False column, then use it to select rows — every filter this semester, however complex, is built from these two steps.

Condenses the guide's line-by-line for Exercise 2. We live-code this in two deliberate stages: stage 1 prints the boolean column itself (the step most guides skip, and the one that actually explains everything); stage 2 places that same column inside df[...] to filter. south = df[...] is a new DataFrame, a genuinely separate object from df — not a live "view" (brief honest caveat: view vs. copy is more nuanced than this lab needs, and resurfaces as a real gotcha in Exercise 5's SettingWithCopyWarning). len(south) is Module 06's len(); south.head() confirms every shown row really has 'South'.

Line-by-line: - deck fixture rebuilds data/retail_sales.csv and df. - df.sort_values('revenue', ascending=False) — sorts the entire DataFrame by revenue; ascending=False means highest-first. The default (omitted) is ascending, so this argument is doing real work, not style. - .head(5) — chained directly onto the sort, no intermediate variable: .sort_values(...) returns a full sorted DataFrame, and .head(5) is called on that result immediately. Name .method1().method2() as a pattern students will see constantly. - top5 = ... — stores the final chained result. Point out explicitly (matching the lab page's own required observation): the leftmost index column (4365, 1913, 3236, ...) is not 0, 1, 2, 3, 4 — it is each row's original position from the unsorted df, carried through the sort. Say plainly: sorting rearranges row order, but doesn't renumber the index. A clean 0–4 index would need an explicit .reset_index(), which this exercise deliberately doesn't ask for so students notice the index isn't automatically reset. Knowledge check

If two rows had the exact same revenue value, how would .sort_values() decide which one appears first?

Ties are broken by original row order by default, unless a secondary sort column is specified — .sort_values() accepts a list of columns for exactly this kind of tie-breaking.

Two-Condition Filter

Teaching goal: combine two conditions in a pandas filter — and confront, directly and deliberately, the fact that this requires & (not and) and parentheses around each condition, a genuinely confusing, easy-to-get-wrong piece of syntax worth a real live demonstration of both failure modes. Say to the class (verbatim): "Combining two conditions in pandas looks similar to Module 5's and, but it is not the same syntax, and using the wrong one produces a genuinely confusing error. I'm going to show you both ways this breaks, on purpose, before showing you the version that works."

The idea — & not and, and parentheses every time

This breaks in two different confusing ways

and/or are for single booleans; &/| are pandas' element-by-element equivalents, built to combine two boolean columns row by row. Using and on two columns raises ValueError: The truth value of a Series is ambiguous.

& has higher precedence than == and > — the opposite of what you'd assume — so every condition needs its own parentheses, every time: df[(df['region']=='South') & (df['revenue']>1000)]. Without them you get a cryptic TypeError.

Condenses the guide's line-by-line for Exercise 4. Rehearse both broken demos before class — both produce genuinely confusing-looking errors the first time. Broken attempt 1 (and): Python's and combines two single True/False values, but df['region']=='South' is an entire column of thousands of booleans — and can't meaningfully combine two whole columns, so it raises rather than guessing. Broken attempt 2 (&, no parentheses): without parens this evaluates as df['region'] == ('South' & df['revenue']) > 1000, trying to &-combine the string 'South' with a numeric column before the comparisons happen. Working version: parentheses around each condition, & between them. Result 116 is smaller than Exercise 2's South-only 1352: & narrows — combining two conditions can only keep the same number of rows or fewer than either alone, never more.
