Read and Print Raw Rows

Teaching goal: open a file safely with a with block, read it with csv.reader, and observe — critically — that every value comes back as a string, even ones that look numeric. Say to the class (verbatim): "New syntax today: with. This is how you open a file safely — it guarantees the file gets closed automatically, even if something goes wrong partway through, without you having to remember to call .close() yourself."

The idea — with is the modern way to open a file

Slow down for this — it's the new syntax

with open(...) as f: creates a block where f (the open file) is available, and automatically closes it the moment the block ends — even if an error occurs partway through.

Contrast with the older, error-prone f = open(...); ...; f.close(), where a forgotten or skipped .close() leaves the file open. Say plainly: with is the standard, correct way to open a file in modern Python — there's essentially no reason to use the manual open/close pattern instead.

This card condenses the guide's line-by-line for Exercise 2. The with block is the segment to protect time for. import csv gives tools that handle CSV edge cases (commas inside quoted fields) a naive .split(",") would get wrong. csv.reader(f) wraps the open file; for row in reader: yields each row as a list of strings, including the header row on the first iteration — this loop doesn't yet distinguish header from data, which is exactly what Exercise 3 fixes.

Exercise 3 · 6 min · 0:16–0:22

Skip the Header

Teaching goal: next() to advance an iterator by exactly one step, pulling the header out of the loop entirely — a small piece of syntax with an outsized payoff for every remaining exercise today. Say to the class (verbatim): "One new function, next(), and it solves the 'header row keeps getting mixed in with data' problem for the rest of this lab."

The idea — next() advances the reader by one

State this mechanism explicitly

reader is an iterator: it hands out one item at a time when asked. next(reader) explicitly asks for "the next item" — called before the loop, it pulls exactly the first row (the header) out and advances the reader's internal position by one.

After that line runs, the reader "remembers" it already gave out the header, so the for loop that follows starts fresh from the second row. A csv.reader only moves forward — never backward, and calling next() again won't "reset" it.

Condenses the guide's line-by-line for Exercise 3. header = next(reader) stores the header row so it can still be used later if needed. print(header) confirms it was captured distinctly from the data rows. for row in reader: then starts at the first genuine data row.

Live-code — Exercise 3

Assuming next() can be called again to "reset" back to the header — it can't; a csv.reader only moves forward. Store the header in a variable instead. Two familiar patterns, new source

The idea — "a" adds, "w" erases
