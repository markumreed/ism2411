Exercise 3 · 10 min · 0:18–0:28

Handle Missing Values

Teaching goal: the lab's first genuine judgment call — drop rows missing essential identifiers, but fill (rather than drop) numeric columns with few missing values — and require students to articulate why each choice fits its specific situation. Say to the class (verbatim): "Two different strategies for two different kinds of missingness, and this is a real decision, not a formula. A missing order_id means we fundamentally don't know what transaction this row represents — there's no reasonable way to guess it, so we drop it. A missing unit_price, on a dataset where it's only missing in a couple of rows, can reasonably be estimated from the other rows' average — so we fill it instead of losing the whole row." Line-by-line: df.dropna(subset=["order_id", "order_date"]) — .dropna() removes rows containing missing values; subset=[...] restricts the check to only the named columns. Say explicitly: without subset, .dropna() checks every column, which is almost never what you want on a real multi-column dataset. The comment above the drop is the exercise's real required content. df["unit_price"].astype(str).str.replace("$", "", regex=False) — preparatory cleanup: some unit_price values are "$xx.xx" strings; .astype(str) makes every value text for this step; .str.replace("$", "", regex=False) strips the dollar sign. regex=False — $ means end-of-string in a regex; regex=False treats it as a literal. pd.to_numeric(..., errors="coerce") — converts the dollar-sign-free strings to numbers; any value that still can't convert becomes NaN rather than crashing. df["unit_price"].fillna(mean_price) — must happen after the string-to-numeric conversion: before conversion, the "missing" values sit alongside dollar-sign strings in an object column where .mean() can't be computed. Common mistakes: calling .fillna() before stripping the "$" and converting — .mean() on a column still containing text errors or silently misbehaves. Dropping rows for any missing value (forgetting subset=) — silently loses the two rows that were only missing unit_price and should have been fixable via fill. Writing a comment that states what was done without the why. Check for understanding (guide, verbatim parenthetical): "If unit_price had been missing in 30 of 42 rows instead of just 2, would filling with the mean still be a reasonable choice? (Much less reasonable — a mean computed from only 12 real values, then imposed on 30 rows, would dominate the column with a single estimated number and could seriously distort any later analysis; a good answer recognizes that the "fill vs. drop" decision genuinely depends on how much is missing, not just that something is missing — directly previewing tonight's first reflection question.)"

The idea — drop essentials, fill estimables, and say why

This is a judgment call, not a formula

A missing order_id or order_date means we can't identify or place the transaction — there's no honest way to guess it, so we drop the row: df.dropna(subset=["order_id", "order_date"]). The subset= is load-bearing — without it, .dropna() drops a row for a missing value in any column.

A missing unit_price, on a dataset where only 2 of 42 rows lack it, can be estimated from the column mean — so we fill instead of losing two otherwise-complete rows. First strip "$" and pd.to_numeric(errors="coerce"), then .fillna(mean_price) — the order matters.
