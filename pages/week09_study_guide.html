Conditionals: tiered business rules

A tiered rule is one decision with several possible outcomes, so write it as one if / elif / else chain.

Bug report 1

The biggest customer got the cheapest rate

A utility bills electricity by monthly usage. Usage below 500 kWh costs $0.10 per kWh, 500 through 999 kWh costs $0.12, and 1,000 kWh or more costs $0.15. A factory used 1,200 kWh, and this code billed it at the lowest rate.

usage = 1200

if usage >= 1000:
    rate = 0.15
if usage >= 500:
    rate = 0.12
if usage >= 0:
    rate = 0.10

print(rate)    # prints 0.1

Find the bug before you open the answer.

Reveal the bug

All three tests are true for 1,200, so all three lines run and the last one wins. The code makes three separate decisions, but the business rule is one decision. Only a chain lets exactly one tier win.

FixOne chain, highest tier first

Turn the three if statements into one chain, so Python stops at the first true test. This version also applies the utility's second rule: a $20 service fee is added when the usage charge is less than $40.

usage = 620

# Decision 1: choose the rate
if usage >= 1000:
    rate = 0.15
elif usage >= 500:
    rate = 0.12
else:
    rate = 0.10

# Calculate once, after the chain
usage_charge = usage * rate

# Decision 2: a separate rule gets its own if
if usage_charge < 40:
    service_fee = 20
else:
    service_fee = 0

total_bill = usage_charge + service_fee

print(f"Usage charge: ${usage_charge:.2f}")
print(f"Service fee: ${service_fee:.2f}")
print(f"Total bill: ${total_bill:.2f}")
Output
Usage charge: $74.40
Service fee: $0.00
Total bill: $74.40

Five habits keep any tiered rule safe:

  • Check the highest tier first and work down. Python stops at the first true condition, so each elif runs only when the tiers above it failed. That is why elif usage >= 500 needs no upper limit.
  • The chain only chooses the rate. Do the multiplication once, after the chain.
  • A separate rule gets its own if. The service fee is not another tier, so it is not another elif.
  • Read which value the rule names. The fee depends on the usage charge, a calculated value, not on the original kWh. Calculate a value before you test it.
  • Give every variable a value on every path. The else sets service_fee = 0, so the final calculation always has a number to add.

Translate boundary words exactly

The rule saysWrite
below 500, less than 500, under 500< 500
500 or more, at least 500>= 500
more than 500, over 500, exceeds 500> 500
500 or less, up to 500, no more than 500<= 500
from 500 through 999>= 500, with the tier above it checked first

Test your chain with the exact boundary numbers. Here, a usage of 500 must land in the $0.12 tier and 1,000 in the $0.15 tier.

Bug report 2

The 15-minute wait that vanished

A call center logs six wait times in minutes, and a wait of 10 minutes or more counts as long. One caller waited 15 minutes, but the manager's report says the longest wait was 9.

wait_times = [4, 12, 7, 15, 10, 9]

long_waits = 0
longest = 0

for wait in wait_times:
    if wait >= 10:
        long_waits += 1
    elif wait > longest:
        longest = wait

print(f"Longest wait: {longest} minutes")    # Longest wait: 9 minutes

Find the bug before you open the answer.

Reveal the bug

elif means "only if the test above failed". Every long wait passes the first test, so Python never asks whether it is also the longest. This is the utility bug in reverse: there, one decision was split into three, and here, two decisions were chained into one.

FixA separate if for each job

Counting long waits and finding the longest are two jobs, so give each its own if. The corrected loop also keeps a running total, so all three patterns work in one pass.

wait_times = [4, 12, 7, 15, 10, 9]

# Set up before the loop
total_wait = 0
long_waits = 0
longest = 0

# Update inside the loop
for wait in wait_times:
    total_wait += wait
    if wait >= 10:
        long_waits += 1
    if wait > longest:
        longest = wait

# Print after the loop
print(f"Total wait: {total_wait} minutes")
print(f"Long waits: {long_waits}")
print(f"Longest wait: {longest} minutes")
Output
Total wait: 57 minutes
Long waits: 3
Longest wait: 15 minutes

Five checks work on any list:

  • Set up before the loop. A variable set to 0 inside the loop is erased on every pass.
  • Indent what repeats; un-indent what happens once. The print lines sit at the left margin, so they run once, after the loop.
  • Use a separate if for each thing you track. One wait can be both a long wait and the new longest, so these checks are not an if / elif pair.
  • Some items match no rule. A value in the middle changes no counter, so a counter often needs no else.
  • Let the loop do the math. Writing total_wait = 57 because you added the numbers yourself is hard-coding, and it is not allowed.
Loop only

Built-in shortcuts such as sum(), max(), and min() are not accepted on the exam. The total, every count, and the highest value must all come from your loop.

Starting highest at 0 works because these amounts are never negative. To find a lowest value, start from the first item instead, such as lowest = wait_times[0].

Explain why longest = 0 goes above the loop while longest = wait goes inside it.

Functions: write the rule once

A function packages one calculation behind a name, so you write the rule once and call it for every item.

Example. A shipper charges $1.50 per pound under 5 lb, $1.00 per pound from 5 lb through 19.99 lb, and $0.75 per pound at 20 lb or more.

def calculate_shipping(weight):      # weight is the parameter
    if weight >= 20:
        rate = 0.75
    elif weight >= 5:
        rate = 1.00
    else:
        rate = 1.50

    cost = weight * rate
    return cost                      # send the answer back
Bug report 3

Four packages shipped for $0.00

The company ran this loop over four packages, and the report showed no shipping cost at all.

package_weights = [3, 12, 25, 8]
total_shipping = 0

for weight in package_weights:
    calculate_shipping(weight)

print(f"Total shipping: ${total_shipping:.2f}")    # Total shipping: $0.00

Find the bug before you open the answer.

Reveal the bug

The function ran four times and returned four correct answers, and nobody caught them. A returned value disappears unless the calling line stores it or uses it.

FixCatch the answer

Store each answer in a variable, then add it to the running total. The function handles one package, and the loop supplies them one at a time.

package_weights = [3, 12, 25, 8]
total_shipping = 0

for weight in package_weights:
    cost = calculate_shipping(weight)
    print(f"Weight: {weight} lb   Shipping: ${cost:.2f}")
    total_shipping += cost

print(f"Total shipping: ${total_shipping:.2f}")
Output
Weight: 3 lb   Shipping: $4.50
Weight: 12 lb   Shipping: $12.00
Weight: 25 lb   Shipping: $18.75
Weight: 8 lb   Shipping: $8.00
Total shipping: $43.25

Check five things on any function answer:

  • The parameter stands for one item. Inside the function, use weight. Never mention the list there.
  • return hands the answer back; print only displays it. A function that prints but does not return gives the caller None, which cannot be added to a total.
  • Catch the returned value. cost = calculate_shipping(weight) stores the answer so you can print it and add it.
  • Define first, call later. Write the def above the loop, never inside it.
  • The total belongs to the loop. Set it to 0 before the loop, add to it inside, and print it after.
🦆 Tell the duck

Explain what happens to the value after a function reaches return.

Why a function is better than repeated code

Expect to explain this in a sentence or two. Three reasons are worth knowing:

  • One place to change. If a rate changes, you edit one function instead of every copy of the rule.
  • Consistency. Every item goes through identical logic, so no copy can drift or contain its own typo.
  • Readability. The loop shrinks to a few lines that say what happens, and the function can be checked with a single value.

Tracing: be the computer

Tracing means running the code on paper one line at a time and writing down each variable as it changes. It is how you check a handwritten answer without a computer.

Trace a function call in four moves

Follow the line cost = calculate_shipping(12):

  1. The call copies 12 into the parameter weight.
  2. 12 >= 20 is false, so Python moves on. 12 >= 5 is true, so rate = 1.00.
  3. cost = 12 * 1.00, which is 12.0.
  4. return cost sends 12.0 back to the calling line, where it is stored in cost.

Mistakes that cost points

These thirteen mistakes break the logic or the rules of the exam, so clear handwriting will not save them. Read each one, predict what goes wrong, then open it to check.

Separate if statements for tiers

What goes wrong: Several can be true, and the last one overwrites the rest.

Fix: One if / elif / else chain.

Lowest tier checked first with >=

What goes wrong: Every large value stops at the first test.

Fix: Check the highest tier first.

> where the rule says "or more"

What goes wrong: The boundary value lands in the wrong tier.

Fix: Translate the words, then test the boundary number.

Testing the original input when the rule names a calculated value

What goes wrong: The second decision uses the wrong number.

Fix: Reread which value the rule names.

Using a value above the line that calculates it

What goes wrong: The program stops with an error.

Fix: Order lines so each value exists before it is used.

total = 0 or count = 0 inside the loop

What goes wrong: The variable resets on every pass.

Fix: Set it up above the for line.

Final print indented inside the loop

What goes wrong: It prints on every pass.

Fix: Un-indent it to the left margin.

sum(), max(), or min() instead of the loop

What goes wrong: Built-in shortcuts are not accepted.

Fix: Add, count, and compare inside the loop.

print instead of return in a function

What goes wrong: The caller receives None.

Fix: End the function with return.

Calling a function without storing the result

What goes wrong: The answer is thrown away.

Fix: amount = my_function(value)

Rewriting the rule inside the loop

What goes wrong: The function is never used.

Fix: Call the function once per item.

Writing an answer you worked out in your head

What goes wrong: Hard-coded results are not allowed.

Fix: Let the code calculate every result.

= inside a condition

What goes wrong: = assigns a value; it does not compare.

Fix: Use == to compare.

Practice 1: Travel reimbursement

Practice 1 · Conditionals

A company reimburses employee travel by trip mileage:

  • Trips under 50 miles are not reimbursed.
  • Trips from 50 through 199 miles are paid $0.40 per mile.
  • Trips from 200 through 499 miles are paid $0.50 per mile.
  • Trips of 500 miles or more are paid $0.60 per mile.

The company also adds a $30 meal allowance if the mileage reimbursement is $100 or more.

Assume:

miles = 240

Write Python code that:

  1. Determines the correct per-mile rate.
  2. Calculates the mileage reimbursement.
  3. Determines whether the $30 meal allowance applies.
  4. Calculates the total paid to the employee.
  5. Prints the mileage reimbursement, the meal allowance, and the total paid.

When you finish, trace your code again with miles = 120 and miles = 200.

Practice 2: Delivery performance

Practice 2 · Loops and conditionals

A restaurant reviews six delivery times, in minutes:

delivery_minutes = [38, 52, 30, 61, 45, 27]

A delivery is late if it takes more than 45 minutes. It is express if it takes 30 minutes or less.

Write Python code that uses a loop to:

  1. Calculate the total delivery minutes.
  2. Count the late deliveries.
  3. Count the express deliveries.
  4. Find the longest delivery time.
  5. Calculate the average delivery time.
  6. Print all five results.

Your loop must do the work. Do not work out any result by hand, and do not use sum(), max(), or min().

Practice 3: Loyalty points

purchases = [12, 35, 60, 48]

Part A. Write a function named calculate_points(amount) that receives one purchase amount, determines the points per dollar, calculates the points, and returns them.

Part B. Write code that creates a variable for total points, loops through purchases, and calls calculate_points() for each one. Print each purchase amount with its points, add the points to the total, and print the total after the loop.
