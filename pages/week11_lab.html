Before You Start: Set Up This Lab’s Repo

From this lab on, every lab gets its own GitHub repo: ism2411-lab11 for this one, ism2411-lab12 for the next, and so on. You write and run your code in a folder on your laptop, then upload it on the GitHub website, the same way you did in Lab 8. The first time takes about ten minutes. After that it takes two.

Why a new repo for each lab

Each lab is its own small project. Its repo holds only that lab’s files and that lab’s commits, so the URL you submit shows exactly one piece of work, and your instructor downloads exactly one lab to grade it. Real projects work the same way: one repo per project.

Your ism2411 repo from Lab 8 stays as it is, with your earlier labs in it. Don’t add new labs to it.

SETUP · ON THE GITHUB WEBSITE
Set up ism2411-lab11
Five steps, in order. Bold words are buttons and menus on github.com.

STEP 1 · MAKE THE REPO ON GITHUB.COM

Click the + at the top right, then New repository. Name it ism2411-lab11 and make it Public. Turn on Add README, and set .gitignore to Python. Leave License at none. Click Create repository.

STEP 2 · MAKE A WORK FOLDER ON YOUR LAPTOP

In VS Code’s terminal (View → Terminal), one line at a time:

cd ~
mkdir ism2411-lab11
cd ism2411-lab11
code .

VS Code opens the folder. Create the lab’s file here with code customers.py. Every file in this lab goes in this folder, and every command runs from here.

STEP 3 · GIVE THE README A TITLE

On your repo page, click README.md, then the pencil icon (Edit this file). Replace the one line GitHub put there with this, and put in your name:

# ISM2411 Lab 11 — Customer Dictionary & Lookup

**Name:** Your Name Here

## How to Run

From this folder:

```
python3 customers.py
```

Click Commit changes..., then Commit changes again. GitHub’s default message is fine.

STEP 4 · UPLOAD YOUR WORK (AFTER EACH EXERCISE OR TWO)

  1. Save the file in VS Code.
  2. On your repo page, click Add file → Upload files.
  3. Drag your whole ism2411-lab11 folder onto the upload area. GitHub keeps the folder, so your file lands at ism2411-lab11/customers.py.
  4. Optional: under Commit changes, replace Add files via upload with a short note on what changed, such as add exercise 3: safe lookup with get. It isn’t graded, but it makes an older version easy to find.
  5. Click Commit changes.

Uploading a file that is already in the repo replaces it. GitHub keeps every earlier version in the commit history, so each upload also backs up your work.

STEP 5 · CHECK WHAT YOUR INSTRUCTOR WILL SEE

Your repo page lists .gitignore, README.md, and your ism2411-lab11 folder. Click the folder to make sure customers.py is inside it. Click the commit count (the clock icon above the file list) to see your commits, newest first, with GitHub’s Initial commit at the bottom. Then open the repo in a private or incognito window. A 404 page means the repo is Private: open Settings → General → Danger Zone → Change visibility.

Hint: which settings do I pick on the New repository page?
  • Repository name: ism2411-lab11, all lowercase, with the two-digit lab number.
  • Public. Your instructor can’t grade a private repo.
  • Add README: on. It gives the repo its first commit and the README you edit in Step 3.
  • .gitignore: Python. GitHub writes the file for you.
  • License: none.
Hint: how do I find my folder to drag it?

Your work folder is in your home folder. In VS Code’s terminal, run cd ~, then open . on a Mac or explorer.exe . on Windows. A Finder or File Explorer window opens on your home folder, and ism2411-lab11 is one of the folders in it. Drag that folder onto the GitHub upload page.

Hint: what do I drag when a lab has folders?

The same thing: your whole work folder. From Lab 12 on, labs have folders such as data and charts, and they come along inside it, so sales.csv lands at ism2411-lab12/data/sales.csv. Dragging the files and folders inside your work folder works too. Pick one way and use it every time for that lab.

Hint: how do I get a downloaded file into my data folder?

From Lab 12 on, you download CSV files from the lab page, and your browser saves them in your Downloads folder. Open Downloads in Finder (Mac) or File Explorer (Windows) and drag the file onto the data folder in VS Code’s Explorer panel. VS Code copies it in. On Windows this also moves the file from Windows into Ubuntu, where your work folder lives. If the name ends in (1), such as sales (1).csv, you downloaded it twice: right-click it in VS Code, choose Rename, and delete the (1).

Hint: my files show up twice

You uploaded both ways: once as the whole folder and once as the files inside it. Delete the older copy: open each of its files, click the ··· menu at the top right, and choose Delete file. If you leave both, your instructor grades the copy you uploaded most recently.

Hint: a file landed in the wrong place, has the wrong name, or shouldn’t be there

Open the file on GitHub, click the pencil icon, and fix the name box. Type data/ in front of a name to move the file into a data folder. Commit the change. To remove a file, open it, click the ··· menu at the top right, and choose Delete file. Dragging a whole folder can bring along hidden files such as .DS_Store or .ipynb_checkpoints. They don’t affect your grade, so delete them or leave them.

Hint: I forgot to set .gitignore to Python

Click Add file → Create new file and type .gitignore in the name box. Click Choose .gitignore template, pick Python, and commit. If you don’t see that button, paste the starter list from Lab 8, Exercise 3 instead.

Hint: mkdir says the folder already exists

You made it already, or you cloned the repo with Git earlier. Run cd ism2411-lab11 and carry on. A cloned folder works fine as your work folder, but it holds a hidden .git folder, so don’t drag the whole thing. Drag the files inside it, or upload with the Git commands.

Hint: there’s no Add file button

You aren’t signed in, or you are on someone else’s repo. Sign in and open https://github.com/YOURUSERNAME/ism2411-lab11.

Prefer the terminal? Use Git commands instead

If git push already works for you, keep using it. Both ways put the same files and commits on GitHub, and both are graded the same way. This 3-minute demo shows the whole loop on a practice repo named simple_lab_11:

After each exercise or two: save in VS Code, then drag your ism2411-lab11 folder in with Add file → Upload files and click Commit changes. Each upload backs up your file. GitHub’s default message is fine; a short note on what changed, such as add exercise 3: safe lookup with get, is optional.

Exercises

EXERCISE 1 · Beginner
One customer
Create one customer dict with at least 4 fields: name, email, tier, ytd_spend. Print each field individually using key access. Then print the whole dict.
Expected: each field on its own line, then the full dict
EXERCISE 2 · Beginner
Update and add
Add a phone field. Update the tier to "platinum". Delete the email field with del. Print the dict after each step so you can see it change.
Expected: 3 printed versions of the dict showing each change
EXERCISE 3 · Beginner
Safe lookup
Use .get() to look up the email field you deleted in Exercise 2 — provide the default "no email on file". Confirm it returns the default rather than crashing. Then use bracket notation to look up the same key and observe the KeyError.
Expected: .get() returns default; bracket notation raises KeyError (catch it with try/except)
EXERCISE 4 · Beginner
Iterate
Print every key:value pair using a for loop with .items(), formatted as "name: Alice". Then try iterating without .items() and explain in a comment what the difference is.
Expected: each field formatted on its own line
EXERCISE 5 · Intermediate
Lookup table
Build tier_discounts = {"bronze": 0, "silver": .05, "gold": .10, "platinum": .15}. Look up the discount for the customer's current tier using .get() with default 0. Compute the discounted price for a $200 purchase. Print the tier, discount rate, and final price.
Expected: tier · discount % · final price all printed
EXERCISE 6 · Intermediate
List of dicts
Build a list customers = [dict1, dict2, dict3] with at least 3 different customers (different tiers). Loop through it and for each customer print their name, tier, and the discount they receive on a $300 purchase using the tier_discounts lookup table.
Expected: one formatted line per customer showing name, tier, discount amount
EXERCISE 7 · Intermediate
Nested catalog
Build a nested product catalog: catalog = {"Widget A": {"price": 9.99, "stock": 150}, "Gadget C": {"price": 49.99, "stock": 8}}. Loop through the catalog and print any product with stock below 20 as a "LOW STOCK" alert.
Expected: only Gadget C triggers the alert
EXERCISE 8 · Advanced
Sales by region
Given a list of transaction dictionaries (each has region and amount), build a summary dictionary where each key is a region name and the value is the total sales for that region. Use a loop and .get(region, 0) to accumulate. Print the final summary sorted by region name.
Sample input: [{"region": "South", "amount": 300}, {"region": "North", "amount": 150}, {"region": "South", "amount": 200}] → South: 500, North: 150

Reflection

Before you submit

In a Python comment at the top of your file, answer these two questions in 2-3 sentences each:

  1. In Exercise 3 you saw the difference between .get() and bracket notation. When in real work would you use each one, and what's your rule of thumb for choosing?
  2. Exercise 8 asked you to build a summary dictionary with a loop. What does this pattern remind you of from Excel, and why might the Python version be more useful for large datasets?
